# 现场演示脚本（验收用）

> 按选题书必做项逐条走通，最后演示加分项（摄像头）。每步给出「做什么 / 预期结果 / 坑」。
> 未知判断阈值已是校准后的 **0.8124**（不是占位值），演示时可以直接说结论。
> 唯一不能由离线环境代替的是**实机**：摄像头、麦克风、TTS 联网、中文字体、权重缓存，开场前 5 分钟逐项确认。

## 0. 开场前检查（5 分钟）

```bash
python --version                 # ≥ 3.10
python -c "import torch, gradio; print(torch.__version__, gradio.__version__)"
python tools/demo_cli.py stats --library ~/.rn18/data/features.json
```

预期 `stats` 输出：物体 5 个、向量 25 条、阈值 0.8124。

逐项确认（任一项不过就现场换方案，不硬撑）：

- [ ] `~/.cache/torch/hub/checkpoints/resnet18-f37072fd.pth` 已存在，首跑不下载
- [ ] `~/.rn18/.env` 有百度 Key，`BAIDU_ASR_DEV_PID=80001`
- [ ] 联网正常（Edge TTS 要用），断网时提前说明播报降级
- [ ] 麦克风有输入电平，摄像头没被别的程序占用
- [ ] 中文字体正常（Windows 自带微软雅黑；Linux 要有 Noto CJK）

## 1. 启动界面

```bash
python app.py
# 浏览器打开 http://127.0.0.1:7860
```

预期：三个 Tab ——「1 · 多图录入」「2 · 单图识别」「3 · 实时识别」。

> 若特征库在 `~/.rn18/data/features.json`，启动前设 `RN18_LIBRARY_PATH`（Windows：`set RN18_LIBRARY_PATH=%USERPROFILE%\.rn18\data\features.json`）。

---

## 2. 必做项①：多图录入并保存特征

- Tab1 输入物体名称 → 上传该物体 **5 张**图片 → 点「录入并保存」。
- 预期：状态栏「已录入「X」：新增 5 条特征」，下方表格出现该物体与条数。
- 逐个录入 5 个物体：`power_bank`、`water_cup`、`earphone`、`keyboard`、`mouse`。
- 预期收尾：表格 5 行，合计 25 条。

坑：没填名称 → 提示先输入；重复上传同一张 → 像素摘要去重，不虚增条数。

> 名称口径：本仓库已入库的是英文目录名，识别结果显示英文名。要中文名就用中文名重新录入，**一份库里不要混用两套命名**。

---

## 3. 必做项②：输入图片返回最相似名称与相似度

- Tab2 上传一张**测试图**（`~/.rn18/data/test/<物体>/01.jpg`，与注册图不同的角度）。
- 点「开始识别」。
- 预期：显示名称 + 相似度（如 `power_bank 0.8828 / 88.3%`）、绿框标注图、前 3 个近邻表。
- 可现场对照：「这张是 power_bank 的测试图，相似度 0.8828，是全库最低的一张，仍然高于阈值 0.8124。」

坑：特征库为空 → 提示先录入。

---

## 4. 必做项③：相似度低判未知物体（阈值 0.8124 已校准）

准备三样未录入的东西（本次校准用的就是这三类）：**乌龙茶、充电头、剪刀**。

- Tab2 上传 `~/.rn18/data/unknown/充电头/充电头1.jpg`（最容易被误判的一张）。
- 点「开始识别」。
- 预期：红色标注框 + 「未知物体」，相似度 **0.7421**，低于阈值 0.8124。
- 再演 `乌龙茶1.jpg`（0.6893）与 `剪刀2.jpg`（0.6282），说明不是只有一个样本凑巧。

现场可以讲的三个数：

| 未知物 | 最近邻（库里最像的） | 最高分 | 判定 |
|---|---|---|---|
| 充电头1 | power_bank | 0.7421 | 未知物体 |
| 乌龙茶1 | water_cup | 0.6893 | 未知物体 |
| 剪刀2 | mouse | 0.6282 | 未知物体 |

- 阈值来源：已知测试图最低 0.8828、未知样本最高 0.7421，取中点 0.8124，两侧各留 0.07。
- 为什么充电头没被误判：它确实最像充电宝（0.7421），但比已知类最低分还低 0.14，阈值不用为它抬到 0.88 以上，所以没有牺牲召回。
- 已知侧验证：10 张测试图全在阈值之上，Top-1 = 10/10。

坑：如果现场拍的新图分数异常低，先确认是否拿错物体，再考虑光线/距离。

---

## 5. 必做项④：语音说出物体名称

- Tab1 填好物体名后，点「语音识别名称」→ 对着麦克风说「鼠标」→ 名称框回填。
- 预期：名称框出现「鼠标。」之类带标点的文本，可键盘改成「mouse」再「录入并保存」，条数 +5。
- 若未配 Key：按钮置灰并提示用键盘，`asr()` 不调用，不崩。

坑：网络不通 → 百度接口报错，界面只显示错误码文案；没麦克风 → 直接键盘输入并说明语音链路已单独验证。

---

## 6. 必做项⑤：语音播报识别结果

- 回到 Tab2，再识别一次已知物体。
- 预期：识别完成后**自动朗读**「识别结果：power_bank」，同时画面出结果。
- 断网时预期：显示「语音播报不可用，请检查网络」，识别结果照常显示——这是降级，不是故障。

坑：第一次合成会慢 1–2 秒（要走网络），别急着点第二下；音量为 0 会被误认为没播。

---

## 7. 必做项⑥：简单界面 + 重启后特征库仍在

- Tab1 点「刷新特征库」：从磁盘重读，表格不变 → 内存与磁盘一致。
- **关掉 `python app.py`，重新启动**，再打开 Tab1。
- 预期：5 个物体、25 条向量、阈值 0.8124 都还在，无需重新录入。

坑：只录入没点「录入并保存」→ 重启后为空。

---

## 8. 加分项：摄像头实时识别 + 教学式录入

**持续识别**

- Tab3 打开摄像头 → 对准已录入物体（如鼠标）。
- 预期：3 秒内画面叠加名称与相似度，未知显示「未知物体」；播报按「结果变化 + 4 秒冷却」，不会连续重复。
- 坑：首帧常黑/过曝，代码会丢前 2 帧预热；画面卡顿就换预置帧序列演示。

**教学式录入（现场最快出效果的一段）**

1. 点「教它」→ 识别与 TTS 同时暂停，开始抓帧。
2. 系统按 ≥0.2 s 间隔抓 5 帧（不是连拍相邻帧，避免特征几乎相同导致分数虚高）。
3. 对着麦克风说新物体名（如「剪刀」）→ ASR 回填名称框。
4. 确认或键盘修改后入库 → 特征库条数 +5。
5. 退出教学态 → 恢复识别与 TTS，冷却计时清零。
6. 再把剪刀对准摄像头：应识别为「剪刀」并播报。

坑：教学录制时 TTS 必须暂停，否则麦克风录到播报音会导致 ASR 识别错；中断（取消）不会留下半条脏数据。

> 注意：教学抓的 5 帧算**注册图**，不能拿来当测试图。演示完若继续讲阈值，要说明"刚才是新录入的物体，阈值是按原来的 5 物体校准的"。
